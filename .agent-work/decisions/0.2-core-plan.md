# KawaPress 0.2 核心能力方案

本文记录 0.1 之后第一批核心能力的已确认决策。开发进度在 GitHub Project「KawaPress Roadmap」中跟踪，每节标注对应 issue。UI 主题体系见 `kawa-ui-theme-system.md`。

## 一、站点与页面 `head`（#5）

站点需要向 `<head>` 加入统计脚本、Open Graph、验证 meta 等任意标签。

```ts
type HeadTag = 'meta' | 'link' | 'script' | 'style' | 'noscript'
type HeadAttrs = Record<string, string | boolean>
type HeadConfig
  = | [tag: HeadTag, attrs: HeadAttrs]
    | [tag: HeadTag, attrs: HeadAttrs, content: string]
```

- 三处来源：`KawapressConfig.head`、`LocaleConfig.head`、frontmatter `head`。三者都是标准 JSON 数据。
- 输出顺序是站点、当前 locale、当前页面。去重交给 `@unhead/vue` 的默认规则，所以页面的 `og:image` 可以覆盖站点的同名 meta。
- Core 在 `Root.vue` 中统一渲染。dev SSR、预渲染 HTML 与客户端导航使用同一份逻辑。
- 只允许上面五种标签。`title` 与 `base` 由 Core 管理，不接受用户配置。
- 第三个元素是原样输出的标签内容。安全由作者负责。
- 不做任何 URL 改写。需要站点 `base` 的地址由作者自己写完整。
- 配置错误在配置归一化或页面加载时立即报错，并给出配置路径或页面路由。

## 二、死链检查（#6）

链接解析属于 Core 的文件路由契约，所以死链检查也属于 Core。

```ts
interface DeadLink {
  /** Markdown 源文件中的原始 href */
  href: string
  /** 去掉 base 的公开路由或公共文件路径，含 hash */
  target: string
  /** 相对 srcDir 的源文件路径，例如 /guide/intro.md */
  source: string
  line: number
  reason: 'missing-page' | 'missing-anchor' | 'missing-file'
}

type DeadLinkIgnore = string | RegExp | ((link: DeadLink) => boolean)

interface KawapressConfig {
  deadLinks?: false | {
    level?: 'error' | 'warn'
    ignore?: DeadLinkIgnore[]
  }
}
```

- 检查对象是 Markdown 链接语法产生的站内链接。原始 HTML `<a>`、Vue 组件里的链接和外部链接不检查。
- 页面链接：归一化后的公开路由必须存在。
- 锚点链接：目标页面必须存在这个标题 ID。范围是 h1 到 h6，包含 `{#id}` 自定义 ID。同页 `#hash` 也检查。
- 其他带扩展名的链接（如 `/files/a.pdf`）：必须对应 `publicDir` 中的真实文件。
- `ignore` 中的字符串精确匹配 `href` 或 `target`；正则同时测试这两个值；函数收到完整的 `DeadLink`。
- `kawapress build` 默认 `level: 'error'`：在全部 Vite 构建完成后、生成静态产物前，一次性列出全部死链，再让构建失败。`level: 'warn'` 只输出警告。`false` 关闭检查。
- `kawapress dev` 只检查页面是否存在和同页锚点，并且只输出警告，不阻塞开发。
- 报告格式为 `源文件:行号  href  原因`。

## 三、`kawapress preview`（#3 的前置）

- `preview` 读取站点配置，在配置的 `base` 下提供 `dist`。访问根路径 `/` 时重定向到 `base`。
- 支持 `--port`，默认 `4173`。

## 四、E2E 测试（#3）

- 位置：仓库根目录 `e2e/`，独立的私有工作区包 `@kawapress/e2e`，使用 Playwright 和 Chromium。
- 对象：`docs` 的生产构建加 `kawapress preview`。另有一组少量冒烟测试运行在 `kawapress dev` 上。
- 每个预渲染路由都检查控制台：出现任何 error 或 hydration mismatch 警告即失败。
- 根目录命令：`pnpm test:e2e`。环境变量 `KAWAPRESS_BASE` 决定被测站点的 `base`。
- CI：新建 `ci.yml`，在 PR 和 `main` 上运行 lint、typecheck、单元测试，以及 `base` 为 `/` 和 `/kawapress/` 的 E2E 矩阵。

## 五、Benchmark（#4）

- 位置：仓库根目录 `bench/`，私有工作区包 `@kawapress/bench`。VitePress 使用精确版本号。
- 同一份 fixture 内容同时生成两个站点，规模为 50、500、2000 页。fixture 只使用两边都支持的 Markdown 语法。
- 双方都开启本地搜索。报告中写明双方各自默认开启的其他能力，例如 KawaPress 的 LLMS 产物。
- 指标：冷构建时间；dev 从启动到首个页面 HTML 返回的时间；首页与一篇指南页的 JS、CSS 体积（原始、gzip、brotli）；Lighthouse 性能与无障碍分数（`--lighthouse` 开启时才跑）。
- 根目录命令 `pnpm bench` 输出 Markdown 表格，并写入 `bench/results/`，同时记录机器信息与版本。
- Benchmark 不进入 CI。
